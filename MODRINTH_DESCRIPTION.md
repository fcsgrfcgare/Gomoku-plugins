# Gomoku — English

Gomoku (五子棋) is a Minecraft minigame plugin for **Paper 1.20.4**. Players compete in a classic five-in-a-row board game on custom-built boards inside per-room void worlds.

**Current version: 1.1.4**

## Features

- Per-room void worlds with async batched board generation — no main-thread stalls
- Wool border preview system (async, chunk-safe)
- 5-in-a-row win detection with a uniform per-move clock (default 60s, configurable)
- Green "your turn" title plus a live countdown in the action bar, for the player on move
- Timeouts void the round — neither player scores
- Dying during a match respawns the player at the configured lobby
- Player stats: wins / losses / draws / score / win rate / level
- Bilingual: Chinese (zh_cn) and English (en), with versioned language files that refresh themselves
- Sidebar scoreboard with separate lobby and in-game layouts, fully configurable and placeholder-driven
- PlaceholderAPI expansion for TAB, scoreboards, holograms, etc.
- Multiverse-Core compatible for world management
- Redstone item to cancel matchmaking, spectator mode

## Setup Flow

Every room command lives under `/gomoku admin`.

1. `/gomoku setlobby` — Set the main lobby. Also mirrors the location into that world's vanilla respawn point. Required before any other command.
2. `/gomoku admin add <room>` — Create a void world and register it as a room (teleports you in, creative mode)
3. `/gomoku admin playerspawn` — Stand where players should start and run this (must be inside the room world)
4. `/gomoku admin dish <size>` — Show the wool border preview where the board will be built (15–64, gap 3)
5. `/gomoku admin fill <line> <fill> <border>` — Generate the board inside the preview border. Every build is cached with its XYZ coordinates and a creation number (1, 2, 3, …), so a misplaced board can be removed with `/gomoku admin delete <no>` — the numbers stay stable even after earlier ones are deleted.
6. `/gomoku admin check <black> <white>` — Set piece names and read the materials from hotbar slots 1–2
7. `/gomoku admin save <room>` — Enable the room for players (must be inside the room world). Saving keeps the **last** built board and drops the rest of the cache — the coordinates only live in memory until then.

### Auto-detecting a hand-built board (wooden axe)

`/gomoku admin add` and `/gomoku admin build` empty your inventory and hand you a **wooden axe** (slot 1). Any wooden axe works — including one pulled from the creative menu; the usage text is stamped on automatically when you hold it.

| Input | Effect |
|-------|--------|
| Hold the axe | usage shown in the action bar; block breaking and block interaction are disabled |
| **Left-click** the middle fill block of a cell | detects the board and writes it into the room |
| **Right-click** | cancels (also cancels an active `admin dish` preview) |

Detection walks the board layer outward until it hits air, then measures the spacing between grid lines and converts that into `size` / `interval` / `line` / `fill` / `center` / `boardY` for the room. After a successful scan just set the player spawn and save.

Limitations of this first version: the board has to be an isolated, square, single-layer structure in the void with a **uniform 3×3 fill per cell** and grid lines between cells — i.e. cell width ≥ 3 (`interval` 3 or 5). Boards generated by `admin fill` with `interval 1` (1-block cells) are not detectable this way.

### Guards

| Rule | Description |
|------|-------------|
| Lobby required | All commands except `setlobby` and `help` require the lobby to be set first |
| No lobby build | `add` and `build` cannot target the lobby world |
| No lobby board edit | `dish` / `fill` / `check` / `delete` cannot be used in the lobby world |
| No lobby spawn | `playerspawn` cannot be used in the lobby world |
| No lobby clear | `clear` cannot delete the lobby world |
| Save in-room | `save` must be used inside the room's own world |
| Add after save | If standing in an unsaved room world, `save` it before `add`ing another |

## Gameplay

- Stones are placed by aiming at a board cell and left-clicking.
- Both players are put in creative mode at their spawn with a full hotbar of their own piece block.
- Every move has the same time budget (`turn-seconds`, default 60). The player on move sees a green **"your turn"** title and a countdown ticking down in the action bar above the hotbar.
- **Running out of time voids the round: neither player is awarded points** (no win, no loss, no draw).
- The first 5 moves skip win detection (a five-in-a-row is impossible that early).
- A full board is a draw. Score is `wins × 3 + draws`.
- Spectators join with `/gomoku spectate <room>` — only rooms that are actually in a match accept spectators, otherwise you get "not in a match". Spectators are dropped into the room in spectator mode.
- When a round ends, everyone in the room — both players and all spectators, plus anyone else still standing in the room world — is teleported back to the lobby.
- A redstone item in the hotbar cancels matchmaking.
- Dying inside a room world — or inside the lobby world — respawns the player at the configured lobby.

## Configuration

`plugins/Gomoku/config.yml`:

```yaml
locale: "zh_cn"     # "zh_cn" or "en"
turn-seconds: 60    # time budget for every move
lobby:
  set: true         # written automatically by /gomoku setlobby
  world: world
  x: -36.5
  y: 76.0
  z: -23.5
  yaw: 0.0
  pitch: 0.0
```

The two lobby hotbar items can be toggled independently:

```yaml
hotbar:
  menu:
    enabled: true   # false = hide the room menu item (existing items are removed too)
    slot: 0
  shop:
    enabled: true   # false = hide the piece shop item (existing items are removed too)
    slot: 7
```

`turn-seconds` is re-read at the start of every turn, so `/gomoku admin reload` is not even required after editing it.

Scoreboard layouts are **not** here — they live in the language files (see below).

## Scoreboard

A per-player sidebar with three layouts: **lobby** while the player is not in a match, **game** while they are playing, and **spectator** while they are watching a match. The layouts live under `scoreboard:` in the **language files** (`languages/zh_cn.yml`, `languages/en.yml`), so each locale can carry its own text and the content travels with `lang-version` refreshes.

- `scoreboard.enabled` — `false` disables the sidebar entirely (players get the vanilla scoreboard back)
- `scoreboard.update-interval` — refresh in ticks, default `20` (1 second)
- `scoreboard.<layout>.title` — sidebar title (32 chars max); `<layout>` is `lobby`, `game` or `spectator`
- `scoreboard.<layout>.lines` — the rows, top to bottom; `""` renders a blank row (64 chars max per row)

Missing keys fall back to built-in defaults, so a hand-trimmed language file still works. Servers that still keep an old `scoreboard:` section in `config.yml` keep working too, but once the language file defines the keys the config copy is ignored and a warning is logged on startup.

The spectator layout exists because a spectator has no opponent — `%gomoku_opponent%` returns `—` for them. Use `%gomoku_black_player%` / `%gomoku_white_player%` to list both sides instead.

Every row goes through `%player%` and all `%gomoku_xxx%` placeholders. PlaceholderAPI is **not required** — our own tokens are resolved internally. When PlaceholderAPI *is* installed, placeholders from other plugins (TAB, Vault, …) are resolved as well.

Changing the layout only needs `/gomoku admin reload`; it re-reads the config and repaints every online player.

## Piece Shop

Players can spend points on **pairs** of black/white piece looks. Config lives in a separate `pieces.yml` (extracted on first start).

```yaml
menu:
  slot: 7                # second-to-last hotbar slot
  material: CHEST
  name: "&e&l棋子商店"
  lore:
    - "&7可用积分: &e{points}"
  size: 27
  title: "&8棋子商店  &7可用: &e{points}"

pieces:
  concrete:
    cost: 20             # 0 = owned by everyone
    black:
      material: BLACK_CONCRETE
      name: "&0墨石"
    white:
      material: WHITE_CONCRETE
      name: "&f白瓷"
```

- A chest item sits in the configured hotbar slot (default `7` = 倒数第二格) and opens the shop GUI when clicked. The item is tagged, cannot be moved or dropped, and is re-issued whenever a player returns to the lobby.
- Each entry is **one pair**: `black` and `white` must both be present and must use different materials — an entry that repeats the same block is skipped with a console warning.
- Buying costs **points** = `wins × 3 + draws − already spent`. Spent points are tracked per player, so the lifetime `%gomoku_score%` is never reduced; `%gomoku_points%` shows what is still available.
- Clicking an owned entry equips it for free; clicking a locked entry buys and equips it in one go.
- The chosen pair is used for that player's stones **only in rooms that did not pin their own pieces**. `/gomoku admin check` marks a room as pinned, and a pinned room always overrides the shop. Rooms that were configured before this feature are detected by their non-default materials/names.
- The piece **names** from the chosen pair are what the game shows in the turn message, the `%gomoku_turn_piece%` placeholder and the item in the player's hotbar.
- Player selections are stored in `pieces-data.json`; `/gomoku admin reload` re-reads both files.

## Language Files

Files live in `plugins/Gomoku/languages/` — `zh_cn.yml` and `en.yml`. Besides all chat messages they also carry the sidebar scoreboard layouts. Each file has a `lang-version`:

- On startup (and on `/gomoku admin reload`) the plugin compares the bundled `lang-version` with the one on disk.
- If the server copy is older it is backed up to `languages/backup/<name>-v<old>-<timestamp>.yml`, then replaced — so upgraded messages reach servers that extracted an older revision.
- To keep local edits, raise `lang-version` in your file above the bundled value.

## Building from source

Requires JDK 17 (configured in `gradle.properties`).

```bash
./gradlew build              # -> build/libs/Gomoku.jar
./gradlew proguard           # -> build/libs/Gomoku-obf.jar (runs build first)
./gradlew clean build proguard
```

Deploy by copying the jar into the server's `plugins/` folder and restarting. Only one Gomoku jar may be present — the plugin name would otherwise collide.

## Lobby

Joining the server **clears the whole inventory and armour**, then only two items are handed out (slots are configurable in `config.yml`):

```yaml
hotbar:
  menu:                 # Nether star: opens the room menu
    enabled: true
    slot: 0
    material: NETHER_STAR
    name: "&b&lRoom Menu"
    lore:
      - "&7Left / right click to open the room list"
  shop:                 # Chest: piece shop
    enabled: true
    slot: 7
```

- Left or right click the nether star → **54-slot room menu**
  - free room = crafting table, click to join (starts matchmaking)
  - running room = redstone block, click to spectate
  - anvil in the bottom middle = auto match
  - each room shows its board size and current player count
- **Right-click a room = start a game against the AI**, which opens a 9-slot row: `empty green empty yellow empty orange empty red empty`

## AI levels

| Colour | Level | Backend |
|---|---|---|
| Green | Easy | Built-in Java AI: 40% chance to miss your five-in-a-row, 55% random moves |
| Yellow | Normal | Built-in AI, 25% chance to pick from the top 5 candidates |
| Orange | Hard | Built-in AI, always the best move |
| Red | Hell | **RapFi engine** (needs `pbrain-rapfi-windows-*.exe`, 15×15 only); shows as grey wool when unavailable |

The built-in AI only considers empty cells within 2 blocks of an existing stone and scores five / open four / four / open three / blocked three / open two, weighting attack above defence.

RapFi speaks the standard Gomocup protocol (`START` / `BOARD…DONE` / `INFO timeout_turn` / `END`) with a 3 second per-move budget, a 20 second watchdog and an automatic fallback to the built-in AI.

## Matchmaking

- Left-clicking a room starts matchmaking; if no human opponent joins within **5 minutes** the game is started against the AI (left-click only)
- The countdown is cancelled as soon as a real opponent joins
- While waiting you hold a "Leave match" redstone — **right-click while holding it** to cancel matchmaking

## During a match

- Slot 9 always holds a redstone tagged with `gomoku:exit_item`: first right-click asks for confirmation, a second right-click **5 seconds later** leaves; clicks within 5 seconds are rejected; after **10 seconds** the timer restarts
- Holding that redstone disables crosshair placement and block placing
- Place a stone by **aiming at a cell and left-clicking** (520-block ray, hit point must be at least 0.3 blocks inside the cell)
- The last move is highlighted with **red wool** on its four sides (kept inside the same cell)
- Results are personalised: the winner sees a green "You win", the loser a red "You lost", spectators get a neutral summary
- When the game ends (or the server stops) the **whole stone layer is cleared** while the board itself is kept

## Sounds

```yaml
sounds:

    sound: BLOCK_WOODEN_DOOR_OPEN
    volume: 1.0
    pitch: 1.0
  place:
    sound: BLOCK_STONE_PLACE
    volume: 1.0
    pitch: 0.8      # 0.5 = deeper and slower, 2.0 = higher and faster; volume 0 = silent
```

## Creating a board (order matters)

```
/gomoku admin add <room>            create a void world and enter edit mode
/gomoku admin dish 15               show the preview (this position becomes the board position)
/gomoku admin fill <line> <fill> <periphery>   build at the preview; the third argument is the boundary
/gomoku admin playerspawn           stand outside the board and set the player spawn
/gomoku admin save <room>           save and enable (the room name is required)
```

- `fill` **requires a preview**; without one it refuses and asks you to run `dish` first
- every `fill` first removes the previous board in that world, so you never end up with two boards
- at game start the plugin **re-scans the grid in the world** to calibrate size / centre / height (log line: `Board calibrated for 'x': 15x15 int=3 center=0,6 y=6`), so stale coordinates can no longer shift the stones

## Wooden axe detection (edit mode)

`admin add` / `admin build` clear your inventory and put a wooden axe in slot 1:

- left-click a **grid line** → the whole board is detected (bounding box, line spacing, cell count), missing line blocks are filled in, and the result is written into the room
- right-click cancels (also cancels a running `dish` preview)
- while held no blocks can be broken or interacted with; any wooden axe (including creative ones) gets the usage lore automatically
- the scan only reads loaded chunks (it can never hang the server), radius 240 blocks, up to 150k blocks per board

# Gomoku — 中文

Gomoku（五子棋）是一款面向 **Paper 1.20.4** 的 Minecraft 小游戏插件。玩家在各自房间的虚空世界中、在自定义搭建的棋盘上进行经典的五子连珠对弈。

**当前版本：1.1.4**

## 功能特性

- 每个房间拥有独立的虚空世界，棋盘异步分批生成 —— 不会造成主线程卡顿
- 羊毛边框预览系统（异步、区块安全）
- 五连获胜判定，每手统一计时（默认 60 秒，可配置）
- 轮到的玩家会看到绿色「该你了」标题，以及动作栏中的实时倒计时
- 超时则该局作废 —— 双方都不得分
- 对局中死亡会在配置的大厅处重生
- 玩家战绩：胜场 / 负场 / 平局 / 积分 / 胜率 / 等级
- 双语支持：中文（zh_cn）与英文（en），语言文件带版本号并可自动刷新
- 侧边栏计分板，大厅与对局使用不同布局，完全可配置且由占位符驱动
- 提供 PlaceholderAPI 扩展，可用于 TAB、计分板、全息影像等
- 兼容 Multiverse-Core，便于世界管理
- 红石物品用于取消匹配，支持观战模式

## 配置流程

所有房间相关命令都位于 `/gomoku admin` 之下。

1. `/gomoku setlobby` —— 设置主大厅。同时会把该位置同步为所在世界的原版重生点。执行其他任何命令前必须先完成此步。
2. `/gomoku admin add <room>` —— 创建一个虚空世界并将其注册为房间（会将你传送进去，并切换到创造模式）
3. `/gomoku admin playerspawn` —— 站在玩家应当出生的位置执行此命令（必须在房间世界内）
4. `/gomoku admin dish <size>` —— 在将要建造棋盘的位置显示羊毛边框预览（15–64，间隔 3）
5. `/gomoku admin fill <line> <fill> <border>` —— 在预览边框内生成棋盘。每次建造都会连同 XYZ 坐标和一个创建编号（1、2、3……）一起缓存，因此放错位置的棋盘可以用 `/gomoku admin delete <no>` 删除 —— 即使删除了前面的编号，其余编号也保持稳定。
6. `/gomoku admin check <black> <white>` —— 设置棋子名称，并从快捷栏第 1–2 格读取材质
7. `/gomoku admin save <room>` —— 对玩家开放该房间（必须在房间世界内）。保存会保留**最后一次**建造的棋盘，并丢弃其余缓存 —— 在此之前，坐标只存在于内存中。

### 自动识别手动搭建的棋盘（木斧）

`/gomoku admin add` 与 `/gomoku admin build` 会清空你的背包，并给你一把**木斧**（第 1 格）。任意木斧都可以 —— 包括从创造模式物品栏中拿出的；当你手持它时，会自动打上用法说明。

| 输入 | 效果 |
|-------|--------|
| 手持木斧 | 动作栏显示用法；禁止破坏方块和方块交互 |
| **左键点击**某格中间的填充方块 | 识别整块棋盘并写入房间 |
| **右键** | 取消（同时取消进行中的 `admin dish` 预览） |

识别会从棋盘层向外逐层搜索，直到遇到空气，然后测量网格线之间的间距，并将其换算为房间的 `size` / `interval` / `line` / `fill` / `center` / `boardY`。扫描成功后，只需设置玩家出生点并保存即可。

这个最初版本的限制：棋盘必须是虚空中独立、正方形、单层的结构，每格为**统一的 3×3 填充**，且格子之间有网格线 —— 即格子宽度 ≥ 3（`interval` 为 3 或 5）。用 `admin fill` 且 `interval 1`（1 格宽的格子）生成的棋盘无法通过这种方式识别。

## 玩法

- 瞄准棋盘格子并左键点击即可落子。
- 双方玩家在出生点都会被设为创造模式，快捷栏装满各自棋子的方块。
- 每一手都有相同的思考时间（`turn-seconds`，默认 60 秒）。轮到的玩家会看到绿色**「该你了」**标题，以及快捷栏上方动作栏中不断减少的倒计时。
- **时间耗尽则该局作废：双方都不计分**（不算胜、不算负、也不算平局）。
- 前 5 手不进行胜负判定（这么早不可能出现五连）。
- 棋盘下满则为平局。积分为 `胜场 × 3 + 平局`。
- 观战者通过 `/gomoku spectate <room>` 加入 —— 只有真正处于对局中的房间才接受观战，否则会提示「未在对局中」。观战者会以旁观模式进入该房间。
- 一局结束时，房间内的所有人 —— 包括双方玩家、所有观战者，以及仍站在该房间世界中的其他人 —— 都会被传送回大厅。
- 快捷栏中的红石物品可取消匹配。
- 在房间世界或大厅世界中死亡，都会在配置的大厅处重生。

## 配置

`plugins/Gomoku/config.yml`：

```yaml
locale: "zh_cn"     # "zh_cn" 或 "en"
turn-seconds: 60    # 每一手的时间预算
lobby:
  set: true         # 由 /gomoku setlobby 自动写入
  world: world
  x: -36.5
  y: 76.0
  z: -23.5
  yaw: 0.0
  pitch: 0.0
```

大厅快捷栏物品可以分别开关：

```yaml
hotbar:
  menu:
    enabled: true   # false = 不显示房间菜单物品（已发放的也会移除）
    slot: 0
  shop:
    enabled: true   # false = 不显示棋子商店物品（已发放的也会移除）
    slot: 7
```

`turn-seconds` 会在每一手开始时重新读取，因此修改后甚至不需要执行 `/gomoku admin reload`。

`config.yml` 的注释会随 `locale` 自动在中文/英文之间切换，配置值保持不变；启动和 `/gomoku admin reload` 时会检查缺失或类型错误的配置项并尝试补默认值。

计分板布局**不在**这里 —— 它们位于语言文件中（见下文）。

## 计分板

为每位玩家显示侧边栏，共三套布局：未在对局中时使用 **lobby**，对局进行中使用 **game**，观战时使用 **spectator**。这些布局位于**语言文件**（`languages/zh_cn.yml`、`languages/en.yml`）的 `scoreboard:` 段下，因此每种语言都可以带自己的文案，内容也会随 `lang-version` 刷新一起更新。

- `scoreboard.enabled` —— 设为 `false` 将完全禁用侧边栏（玩家恢复使用原版计分板）
- `scoreboard.update-interval` —— 刷新间隔（单位：tick），默认 `20`（1 秒）
- `scoreboard.<layout>.title` —— 侧边栏标题（最多 32 个字符）；`<layout>` 为 `lobby`、`game` 或 `spectator`
- `scoreboard.<layout>.lines` —— 各行内容，自上而下；`""` 渲染为空白行（每行最多 64 个字符）

缺失的键会回退到内置默认值，因此手工精简过的语言文件依然可用。仍在 `config.yml` 中保留旧 `scoreboard:` 段的服务器也能继续工作，但一旦语言文件定义了这些键，配置中的副本就会被忽略，并在启动时记录一条警告。

之所以需要观战布局，是因为观战者没有对手 —— 对他们而言 `%gomoku_opponent%` 会返回 `—`。可以改用 `%gomoku_black_player%` / `%gomoku_white_player%` 来列出双方。

每一行都会经过 `%player%` 以及所有 `%gomoku_xxx%` 占位符的替换。PlaceholderAPI **不是必需的** —— 插件自有的占位符由内部解析。如果*确实*安装了 PlaceholderAPI，其他插件（TAB、Vault……）的占位符也会一并解析。

修改布局后只需执行 `/gomoku admin reload`；它会重新读取配置并刷新所有在线玩家。

## 棋子商店

玩家可以花费积分购买黑/白棋子外观的**成对**组合。配置位于单独的 `pieces.yml`（首次启动时生成）。

```yaml
menu:
  slot: 7                # 快捷栏倒数第二格
  material: CHEST
  name: "&e&l棋子商店"
  lore:
    - "&7可用积分: &e{points}"
  size: 27
  title: "&8棋子商店  &7可用: &e{points}"

pieces:
  concrete:
    cost: 20             # 0 = 所有人已拥有
    black:
      material: BLACK_CONCRETE
      name: "&0墨石"
    white:
      material: WHITE_CONCRETE
      name: "&f白瓷"
```

- 一个箱子物品会放在配置的快捷栏格位（默认 `7` = 倒数第二格），点击即可打开商店界面。该物品带有标签，无法移动或丢弃，并且玩家每次回到大厅时都会重新发放。
- 每个条目都是**一对**：`black` 与 `white` 必须同时存在，且必须使用不同材质 —— 重复使用同一种方块的条目会被跳过，并在控制台输出警告。
- 购买需要消耗**积分** = `胜场 × 3 + 平局 − 已花费`。已花费积分按玩家单独记录，因此历史累计的 `%gomoku_score%` 永远不会减少；`%gomoku_points%` 显示当前仍可用的积分。
- 点击已拥有的条目即可免费装备；点击未解锁的条目会一次性完成购买并装备。
- 选定的组合只会在**未固定自身棋子的房间**中用于该玩家的棋子。`/gomoku admin check` 会将房间标记为已固定，而固定过的房间始终优先于商店设置。在此功能之前配置过的房间，会通过其非默认的材质/名称被识别出来。
- 游戏在轮次提示、`%gomoku_turn_piece%` 占位符以及玩家快捷栏物品中显示的，是所选组合的棋子**名称**。
- 玩家的选择保存在 `pieces-data.json` 中；`/gomoku admin reload` 会重新读取这两个文件。

## 语言文件

文件位于 `plugins/Gomoku/languages/` —— 即 `zh_cn.yml` 与 `en.yml`。除所有聊天消息外，它们还包含侧边栏计分板布局。每个文件都有一个 `lang-version`：

- 启动时（以及执行 `/gomoku admin reload` 时），插件会将内置的 `lang-version` 与磁盘上的版本进行比较。
- 如果服务器上的副本较旧，会先备份到 `languages/backup/<name>-v<old>-<timestamp>.yml`，然后替换 —— 这样升级后的文案也能送达那些曾解压过旧版本的服务器。
- 若要保留本地修改，请把你文件中的 `lang-version` 提高到内置值之上。

## 大厅

进服时**强制清空背包和盔甲**，然后只发两件物品（位置可在 `config.yml` 调）：

```yaml
hotbar:
  menu:                 # 下界之星: 打开房间菜单
    enabled: true
    slot: 0
    material: NETHER_STAR
    name: "&b&l房间菜单"
    lore:
      - "&7左键 / 右键 打开房间列表"

    enabled: true
    slot: 7
```

- 左键或右键下界之星 → **54 格房间菜单**
  - 空闲房间 = 工作台，点击加入（开始匹配）
  - 对局中房间 = 红石块，点击观战
  - 底部中间铁砧 = 自动匹配
  - 每个房间显示棋盘尺寸和当前人数
- **右键房间 = 直接和 AI 开局**，弹出 9 格等级选择：`空 绿 空 黄 空 橙 空 红 空`

## AI 等级

| 颜色 | 等级 | 后端 |
|---|---|---|
| 绿 | 简单 | 内置 Java AI，40% 不堵你的成五、55% 随机落子 |
| 黄 | 普通 | 内置 AI，25% 从前 5 名候选随机 |
| 橙 | 困难 | 内置 AI，始终最优 |
| 红 | 地狱 | **RapFi 引擎**（需 `pbrain-rapfi-windows-*.exe`，仅 15×15）；未接入时显示灰色羊毛 |

内置 AI 只算已有棋子周围 2 格，按五连/活四/冲四/活三/眠三/活二评分，进攻权重高于防守。

RapFi 走标准 Gomocup 协议（`START` / `BOARD…DONE` / `INFO timeout_turn` / `END`），单步 3 秒上限、20 秒看门狗，失败自动回退内置 AI。

## 匹配

- 左键房间开始匹配，**5 分钟**未等到真人 → 自动转 AI 对局（只对左键生效）
- 匹配中或开局时匹配到真人，计时立刻作废
- 等待匹配时手上有一颗「退出对局」红石，**手持右键**取消匹配

## 对局中

- 第 8 格固定发放带 `gomoku:exit_item` 标签的红石：右键第一次提示确认，**5 秒后**再右键退出；5 秒内点击无效；超过 **10 秒**重新计时
- 手持该红石时不触发射线落子、不能放置方块
- 落子方式：**瞄准格子左键**（520 格射线，命中点需在格子内 0.3 格以上）
- 最近一步棋子四周用**红色羊毛**高亮（同格子内，不会越界）
- 胜负只告诉本人：赢家看到绿色「你赢了」，输家看到红色「你输了」，观战者看中立总结
- 对局结束 / 停服时**棋子层整片清成空气**，棋盘本体保留

## 建棋盘流程（严格顺序）

```
/gomoku admin add <房间>            建虚空世界并进入编辑模式
/gomoku admin dish 15               生成预览（位置就是最终棋盘位置）
/gomoku admin fill 线 填充 外围      按预览位置铺板，第三个参数是边界，边界及之外不能落子
/gomoku admin playerspawn           站在棋盘外侧设置出生点
/gomoku admin save <房间>           保存并启用（必须带房间名）
```

- `fill` **必须在有预览时执行**，否则提示先 `dish`
- 每次 `fill` 会先清掉这个世界里上一次的棋盘，避免出现多块板
- 开局时插件会从世界**重新扫描井字格**校准尺寸/中心/高度（日志：`Board calibrated for 'x': 15x15 int=3 center=0,6 y=6`），所以配置里的坐标不会影响落子准确性

## 木斧识别（编辑模式）

`admin add` / `admin build` 会清空背包并在第 1 格给一把木斧：

- 左键点**井字线** → 自动扫描整块棋盘（外接框、线间距、网格数），缺失的线自动补齐，结果直接写入房间
- 右键取消（同时取消 `dish` 预览）
- 手持时不破坏方块、不触发方块交互；任意木斧（含创造模式取的）都会被自动打上用法
- 扫描只读已加载区块（不会卡服），半径 240 格，单块棋盘最多 15 万方块

# 1.1.4 更新日志

## 新增
- 新增 `/gomoku gui` 与 `/gomoku pieceshop`，所有玩家可打开房间列表和棋子商店界面。
- 大厅快捷栏物品可独立开关显示：`hotbar.menu.enabled`、`hotbar.shop.enabled`；关闭时已发放的物品也会被移除。
- `config.yml` / `pieces.yml` 的注释随 `locale` 自动切换中英文，配置值保持不变；切换前备份为 `config.yml.bak` / `pieces.yml.bak`。
- 启动和 `/gomoku admin reload` 时自动检查配置：缺失或类型错误的键会补默认值并提示。
- 房间世界整世界备份与重置：`/gomoku admin save` 备份到 `plugins/Gomoku/backups/<room>`，对局结束后自动恢复，清除 TNT、庆祝方块、烟花与棋子。
- 赢家庆祝生成间隔：`win-celebration.interval-ticks` 与 `win-celebration.corner-fireworks.interval-ticks`。
- 房间棋子默认名随语言：中文“黑子/白子”，英文“Black Stone/White Stone”。
- 大厅保护 `lobby-protect`：仅管理员+创造模式可破坏/交互；房间沿用原保护逻辑。
- SQLite 本地存储（`storage.type: sqlite`），驱动已内置，无需额外下载。
- 控制台支持英文 `gomoku admin reload`，避免中文乱码。
- 中文/英文配置模板：`config.yml` / `config_en.yml`；棋子模板：`pieces.yml` / `pieces_en.yml`。

## 修复
- 快捷栏“棋子商店 / 房间菜单”物品名不随 `locale` 更新的问题；进服和 reload 会原地重绘已有物品。
- `admin save` 因 `session.lock` 导致整世界备份失败。
- 重置世界时房间内仍有玩家会跳过；现在先把剩余玩家传回大厅再重置。
- 旧配置 `hotbar.menu.name` / `pieces.yml menu.name` 覆盖语言文本的问题。
- 配置注释切换时中英文注释行被错误合并的问题。

## 语言
